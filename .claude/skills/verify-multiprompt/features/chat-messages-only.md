# Messages only

## Sub-features

- Tool/activity blocks never paint ticks, summaries, details, diffs or images and reserve no height or surrounding gap.
- The transcript cache still contains all twelve completed calls and results, including the three reported app-smoke/status summaries.
- Real message rectangles and pixels stay unchanged when those calls stream in. The existing composer draft remains editable and unchanged.
- A centered compact pill above the composer counts new messages that arrive while the reader is scrolled up, with a down arrow, the full count and a separate close control. It reserves its own row outside the transcript, above any visible permission row; ordinary working state reserves no strip.
- Only new transcript message starts count. Initial loads, older pages, repeated refreshes, streamed continuations, Markdown blocks and tool activity never count.
- Ordinary scrolling retains the count until the existing bottom threshold is reached. Reaching bottom clears it; clicking the pill follows the existing End-key scroll path and clears it; close hides the pill without clearing the counter. There is no setting, flag, shortcut or palette command.
- IGSH-814 adds one thin NEW divider above the first unread source message when a chat is reopened. Leaving Chat View or a tab saves the last fully visible message; bottom and sending mark the loaded tail read. The per-chat marker survives restart and layout reconciliation in the existing session JSON and launch snapshot, without another storage file. It is a stable fingerprint of the source message ID and conversation ID, not a timestamp or row index. Timestamped ID-less Codex records use a canonical-record fingerprint, with reader and native round-trip regressions.
- If the saved ID is missing, one plain `Earlier read position is unknown` line replaces NEW; no guessed boundary is drawn. Legacy chats without a saved marker and fully read chats have no line. The divider is independent of the below-fold pill and introduces no setting, shortcut, timer or palette row.
- Native layout regressions cover leading, interleaved and trailing tools, all statuses, expanded details/diffs, incremental layout reuse, message copying, scroll coordinates and unchanged source data.

## How to get to it (user POV)

Open a conversation in Chat View with Alt+C. Assistant messages remain; tool activity does not appear. Scroll up and let messages arrive to see the unread pill above the composer; click it to jump to the newest message or its close control to dismiss it. The unread pill has no setting of its own.

IGSH-816 adds the CLEAN chat view option: the Ctrl+K entry `Chat View: Toggle CLEAN chat` hides read receipts, outbox status rows (including "Queued in Claude" chips), the status footer and empty/history status lines, so only message bubbles remain (IGSH-849 removes the working indicator in both modes; permission controls retain their independent row). It is off by default, persists across restarts, has no keyboard shortcut, and leaves the view unchanged when off. After `messages-only-after-tools.png`, the same messages-only plan opens Ctrl+K through the ownership-checked `Press` SendInput helper, types `clean chat` one key at a time, requires exactly one filtered result, and presses Enter without an arrow-key selection step. Search is a case-insensitive substring match against `chat view toggle CLEAN chat`, not the colon-bearing displayed label. Require the persisted setting to be on and the composer unchanged, then capture `clean-chat-on.png` and `clean-chat-on.bmp`. Repeat exactly that palette path, require the persisted setting to be off and the composer unchanged, and capture `clean-chat-off.png` and `clean-chat-off.bmp`, without sending or adding a message between the captures. The RGB oracle requires identical transcript message pixels in both modes, painted status/outbox/footer rows when off and background-only rows when on, a background-only composer gap in both modes with no reserved working-strip height, nonblank messages in both images, and off-mode transcript and footer pixels identical to `messages-only-after-tools.bmp`. The current two-message scene exercises the model footer, not every possible outbox/receipt state; existing native CLEAN painter regressions cover those other states. The existing user-visible sentence in `changelog.d/IGSH-816-clean-chat.md` is retained; no version changes are needed.

- No Windows app, tests, copied fixtures or builds run on the VPS. All execution happens on GitHub's free Windows runner.
