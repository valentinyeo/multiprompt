# Session restore

Reopen the workspace and local CMD session that was selected, after an updater restart, a normal close or a killed process, including whether it was open in Starred or its home workspace.

## Sub-features

- `normal-close-selection`: the grouped middle-created CMD session returns selected after WM_CLOSE and relaunch.
- `process-kill-selection`: a different selected session returns after Stop-Process and relaunch.
- `starred-view-selection`: a favorite selected in Starred returns in Starred with the same session after a normal close.
- `favorite-home-selection`: that same favorite selected at home returns at home, not Starred, after a killed process.
- `favorite-cross-workspace-selection`: open Starred from workspace A, select a favorite whose home is workspace B, and retain Starred, that session and its unchanged home after both normal close and process kill.
- `update-restart-selection`: from Starred opened in workspace A with the workspace B favorite selected, launch the real updater helper with `--relaunch-after <old app PID>`, close the old app with WM_CLOSE, and require the same view and unique session name after restore.
- `workspace-selection`: all relaunches return to the same non-initial workspace, identified by its saved workspace ID.

## How to get to it (user POV)

- Ctrl+N creates a workspace with its initial CMD session.
- Ctrl+K, type `new cmd`, Enter creates another local CMD session; F2 renames the active session.
- Ctrl+K, type the unique session name, Enter selects that exact session. Ctrl+1 through Ctrl+9 instead use visible row order, which automatic sorting can change.
- Ctrl+K → `Move to Group` → `New group` creates a sidebar group and opens its name editor. Repeat `Move to Group` and choose the group name to add another session.
- Ctrl+K → `Tab Order: Manual` keeps creation order. In Starred, Ctrl+Shift+Down reorders favorites using their independent Starred memberships, without changing their home `group_id`.
- Alt+S favorites the selected session; Alt+1 opens Starred. Select the favorite there by its unique palette name. Alt+2 through Alt+9 return to stored workspaces.
- Close the app window normally, or end its process, then open Multiprompt again.

## Gotchas

- Session shell IDs can be reassigned during restoration. Resolve the published active ID to the unique user-created name; do not assume the previous process's ID survives a relaunch.
- Startup's painted launch snapshot is not proof of completed restoration. The driver requires the new HWND in published state and the new launch's restore/browser phase before checking selection.
- Only this job's private directory is reused. No shared desktop, credentials, synthetic sessions or test-only setters are used.
- Waits are inside the GitHub verification script only. This journey adds no app startup limits, timeouts or blocking behavior.
- Why the old ungrouped journey passed master: with no shared nonzero `group_id`, `normalizeGroupOrder` cannot move any session. Group creation alone is also insufficient because home group assignment immediately normalizes members together. Starred's real reorder shortcut splits the home group without changing its IDs.
- Master failure, independently for updater WM_CLOSE, normal WM_CLOSE and both cross-workspace close/kill stages: save `[A, first H, last 0, middle H*]` with selected index 3. Restore spawns in saved order, then normalization produces `[A, first H, middle H, last 0]`. All restored non-Keep-Alive CMD PIDs are still zero, so master keeps index 3 and selects `Restore last`, not `Restore middle`. The unique-name assertion fails even though last is also a favorite; the view/workspace checks remain mandatory. The combined journey stops on its first failure, not after running the later stages.
- PID timing is not a remote-only premise: `console.spawnShellWithSession` uses `launch_cache.pending` for every kind, including CMD. Its local `PROCESS_INFORMATION` is zeroed; the asynchronous branch does not populate it and copies PID zero to the shell with `console_inflight = true`. The worker only sets its job PID and posts `WM_STARTUP_SHELL_READY`; the UI timer calls `finishStartupShell` to install it after the synchronous `restoreSession` call returns. No reconnect delay or large session count is needed.
- Fixed success uses both app commits. The Favorites fix restores the painted snapshot's Starred flag, so a current Starred snapshot can skip normalization entirely; do not claim it reorders in that case. If normalization runs (including the existing favorite-home-kill stage), the shell-ID fix re-finds middle at index 2 regardless of PID zero. Both paths preserve the name/view/home assertions. This is source-backed reproduction reasoning, not a claimed Windows red/green execution.
- This local CMD journey does not verify remote transport reconnection, account synchronization, browser panes or multiple top-level windows.
