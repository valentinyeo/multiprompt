# Rooms

Source files: src/room*.zig, src/room_service.py, src/room_bridge.py, .claude/skills/verify-multiprompt/rooms-driver.ps1, .claude/skills/verify-multiprompt/rooms-*.py, .claude/skills/verify-multiprompt/rooms-desktop.cs

## Sub-features

Create a shared conversation, add two live chats, send to everyone, mention one member, and compare reply order across the room and the members' own chats.

## How to get to it (user POV)

Ctrl+K **New room** (also available as Ctrl+Shift+N), enter a name, Tab into member search, select Alpha with Enter, then Ctrl+Enter to create. The app requires at least one member when creating. Ctrl+K **Edit room**, search each additional member and press Enter to select it, then Ctrl+Enter to save. Open the room by its name in Ctrl+K. Type into its composer and press Enter. Type `@Alpha TARGET534` to address Alpha alone. Open Alpha and Bravo through Ctrl+K to inspect their own Chat Views.

## Driving it with control.ps1

Dispatch `gh workflow run verify.yml --ref <branch> -f feature=rooms`. The workflow discovers this file automatically; there is no global pull-request smoke entry. Source mapping selects it for room files and its own driver only. Automatic `all` matrices omit Rooms; explicit dispatch (including manual `all`) includes it. The Rooms build profile uses `-Drooms-preview=true`, matching the shipped release feature without enabling it in other verification builds.

`drive.ps1 -Feature rooms` records the desktop with the existing FFmpeg recorder and delegates through `control.ps1` to `rooms-driver.ps1`. Only GitHub-hosted Windows, an isolated profile, the runner-owned account Worker, WSL2 OpenSSH/tmux, FFmpeg and Tesseract are supported. The production account service runs locally with disposable credentials, a runner-only certificate and two seeded saved chats. Initial saved chats, the user SSH configuration and provider commands are fixture setup, not proof of room creation. The room transport runs plain `ssh remote-1` against the user's own SSH configuration, so the fixture writes `home/.ssh/config` for the user profile and authorizes the profile's `id_ed25519` on the runner host before launch, then proves it with a plain SSH preflight. The driver never seeds a room or sends a room command outside the app.

First try Ctrl+K New room on the fresh profile, before private chat driving can warm Rooms. The product publishes the desktop's shared chat helper itself on room create and on room send, so a brand-new runner account needs no warm-up: after the first create the driver asserts `debug.log` carries one of the room bridge lines `[room_bridge] published runtime <digest>` or `[room_bridge] runtime already published <digest>`, and saves the matched line as `room-bridge-published.txt`. The room assertions are unchanged. Then send `PRIVATE534` through each chat's real composer and copy its visible reply. The deterministic stream-json provider replaces only paid Claude; Windows input, SSH, production host, connector, room bridge, persistence and transcript loading remain real. No model calls or shared servers are used. Controlled provider gates hold replies until the driver leaves the room or restarts its owned desktop; a one-time provider error exercises failed-turn recovery.

Each step writes `step-N.png`, `step-N-visible.txt`, `step-N-state.json`, `step-N-debug.log` and a `result.json` case with PASS / FAIL / UNREACHABLE, symptom and recording-relative seconds. A failure does not stop independent later steps. UNREACHABLE names the missing saved prerequisite; it is not a pass. `driverErrors` distinguishes setup or evidence failures from product assertions. `debug.log` is the main profile's log and `fresh-debug.log` the second profile's, so the per-step logs survive the fresh-install step. `journey.mp4`, `actions.json`, `doctor.json`, `build.json`, read-only server snapshots and sanitized `data/` survive cleanup in `verify-rooms`. Require every reachable desktop check to pass, no driver errors, readable video, zero owned app/service processes and removed scratch for a green gate. Phone and lost-acknowledgement limitations remain explicit UNREACHABLE cases, not passes. Room screenshots that need more than one viewport use `*-page-N.png` and `*-all-visible.txt`.

Download with `gh run download <id> -n verify-rooms -D <directory>`. Inspect the screenshots as images and the recording, not just OCR. Timestamps in the cases use the child's clock, which starts just after the outer recorder; use the screenshots to locate the exact frame.

## Gotchas

- The room's own message text is custom-painted and small, so step 3 reads a crop of the room window with several scales and thresholds (`Read-Room`) instead of one full-screen OCR pass. A whole-screen read has misread `BROADCAST534` as `BROADCASTS534` and failed a message that the screenshot plainly showed. The expected text is unchanged; a room that does not show the message still fails.
- Room text is custom-painted and has no copy-all action. Tesseract reads actual desktop screenshots; saved room events independently prove what persisted. Member checks also retain `*-list.png`, cropped below the native member-search field, so typed query text or sidebar names cannot masquerade as picker results. Each list read cuts the row's avatar column off the left edge (the app draws the name 52 px after the row's left) and tries several scales and thresholds, keeping every variant's text in `*-list-variants.txt`; the avatar alone made Tesseract return nothing for a row that was plainly on screen. OCR failures need visual review before being called product bugs.
- The member rows have no accessibility text, so UI Automation cannot supply the names; reading the list means reading pixels.
- Display names and the app's generated mention aliases are different. This journey deliberately checks the requested `@<name>` user path; do not replace it with a private generated ID to hide a failed name mention.
- A failed broadcast reply does not prevent testing a targeted send or opening both member views. No reply order can be proven when no replies exist; report that missing prerequisite explicitly.
- This checks one desktop plus both member chat views and saved server state, not a second physical desktop or Android. `tools/verify-account-photos/android.sh` is a photo-only companion instrumentation harness; it has no Rooms read/retry actions and cannot run in this Windows job. Cases g/h name that missing prerequisite.
- Assistant replies must exist in each member's saved transcript as assistant messages in the same order. A reply's text appearing only inside quoted room context in a user message is not shared reply proof.
- Before each independent send, the driver clears any earlier unsent draft through Ctrl+A and Backspace. A refused display-name mention must not contaminate later away/restart messages.
- The room member search keeps the previous query: Ctrl+A in that field leaves the text in place, so a second name is appended and the list goes empty. The driver deletes the query one Backspace at a time, proves the field is empty through the edit's own text, and only then types the next name. A search that will not clear is a driver error, never a missing-member verdict.
- Closing a tab is Ctrl+Shift+W. Ctrl+W belongs to the browser pane and closes no tab (`src/shortcuts.zig` `sessionCloseShortcut`); the driver presses Ctrl+Shift+W, proves the saved tab is gone, and retries the close up to three times.
- The room composer does not clear with Ctrl+A and one Backspace. The driver deletes a kept draft one Backspace per character and proves the field is empty before typing.
- The journey is allowed to fail on master. Do not add it to unrelated PR smoke gates or change product code to make this verification PR green.
