# Opt-in laptop sync (ISSUE-252)

Ctrl+K → **Sync between laptops** toggles the local `account-sync.json` setting, initially OFF. F1 lists the same action. No dedicated shortcut is reserved. Sign in on each laptop, then opt in on each. Turning it off preserves local files and the journal, and stops all sync timer wakeups. Signing in alone does not transfer layouts, hosts or SSH keys.

## Existing implementation and stores

PR #12, “Sync server slots with account settings”, added `hosts` feature negotiation on `GET|PUT /v1/layout`: three slots with `slot`, `name`, `hostname`, `port`, `user` and optional public `host_keys`. It discovered `ssh -G` aliases, imported only missing slots, appended public known-host keys, and unioned hosts on the server, so deletions could not propagate. It used whole-layout revisions, 409 retries and three-way rebasing. IGSH-423 added `settings` negotiation for `frequent`, `favorites`, `all`, `frequent_first`. Authentication uses the same account service, PKCE sign-in, DPAPI-protected rotating tokens, and serialized account worker. Legacy API behavior remains available to other clients; this desktop no longer uses it for automatic sync.

The complete machine-readable field inventory is [sync-fields.json](sync-fields.json). Its session field list is checked against the actual serializers, including delegated visit/input/archive serialization. Every field is marked **sync** or **never-sync**, and unknown SSH options default to never-sync.

- Hosts: source is the local SSH config, resolved with `ssh -G`; only the three existing portable slot aliases are supported. Sync `slot`, display `name`, resolved `hostname`, `port`, `user`. Never sync public or private keys, host keys, known_hosts, certificates, passwords, identity agents, proxy commands, jump-host configuration, or arbitrary SSH options. Existing SSH identity/proxy options remain on the device; remote hosts still require local SSH credentials and normal host-key verification.
- Workspaces: `session.json` / `session-<workspace-id>.json` contain logical workspace names; `windows.json` / `windows-dev.json` contain registry `version`, `windows`, `id`, `name`, `restore`, `host`. Only names and session membership sync, not local registry IDs, restore policy, window association or the local workspace-order ID list. Workspace names are record identities; rename is delete plus add.
- Remote sessions: sync `kind=tmux`, `name`, `manual`, `favorite`, `used`, `input`, `visits`, `tmux_session`, `tmux_host`, and workspace name. Local numeric membership is converted to the portable name. Session identity is host slot plus case-folded tmux name. Local CMD/PowerShell/WSL/Git Bash sessions never sync; their processes and paths cannot be resumed on another machine.
- Never sync any remaining session-file field: runtime IDs/PIDs, local workspace IDs, active selections, snooze and restore state, grouping, browser URLs/profiles, chat IDs/drafts/transcripts, archive snapshots, attention state, audio and UI preferences, local paths, font/theme choices, browser split geometry, positions/sizes/monitors/DPI. Workspace and tab array order is canonical record order rather than device window order. A field named `name` inside a local group is not a portable workspace/session name and stays local. Wrapper arrays contain only projected portable records, never raw local JSON.
- The four existing split flags sync as one settings record while laptop sync is enabled. Opt-in, account scope hash, pending-file timestamps and journal snapshots never sync; only the record allowlist is sent. Account sign-in tokens never enter documents. Existing explicit **Account: Approve devices** is a separate key-approval feature, not part of laptop sync.

## Protocol and reconciliation

`GET|PUT /v1/sync-records` uses the existing authenticated account service. Each document has `kind`, stable `id`, `updated_at` (Unix milliseconds), `device_id`, `deleted`, and exactly one typed payload, or no payload for tombstones. The server stores one row per account/kind/id and applies an atomic last-writer-wins upsert, ordered by timestamp then device ID. A monotonic local stamp avoids same-device ties; unchanged records are not restamped. A batch never replaces another account or a whole layout. Unknown fields and secrets are rejected rather than silently forwarded.

Local files remain authoritative. Session saves first commit local JSON, then atomically save a redacted pending snapshot and timestamp. The worker diffs the last locally observed projection, journals record edits before networking, pulls, merges, pushes, then separately reads back. Every outgoing record must be present unchanged or superseded by a newer winner before any remote layout or host configuration is applied. If the endpoint is missing, offline, rejects data, returns an incomplete readback, or local capacity is exceeded, local files remain intact and the journal is retried. A failed SSH discovery is not a deletion. A changed SSH config during the request aborts application rather than overwriting a concurrent local edit.

The journal is scoped by a hash of the authenticated account ID, preventing another account's records from being uploaded. Tombstones are retained indefinitely (no unsafe age-based garbage collection); at the 4096-record bound sync fails closed rather than pruning deletion history. Missing-parent sessions are retained as records but not attached until their workspace exists. Remote closure removes only sync-owned local attachments and never kills a remote tmux process. Existing local sessions and machine-local session properties remain intact. Edits made while a request is in flight are rebased locally and published as a subsequent record edit.

One one-shot `TIMER_ACCOUNT` serves the 2-second save debounce, startup pull, 3-minute freshness interval, and exponential 20/40/80/160/300-second failure retry. No independent save timer, background polling loop, or disabled-state wakeup is added. Authentication is still performed at startup even when sync is off.

## Server rollout

This change adds the `sync_records` table and `GET|PUT /v1/sync-records` endpoint with account-service tests. **Not deployed by this change.** A service owner must apply the additive schema and deploy the Worker separately before opting in can round trip successfully. No existing `layouts` seed is needed for the new endpoint, and legacy snapshots are not silently imported. Host/workspace/session metadata is plaintext in D1, like existing layout metadata; this is not end-to-end encryption.

## Evidence

`src/account_records_test.zig` runs two simulated devices against a serialized fake server and proves add, edit, delete, same-host conflicts in both arrival orders, independent edits, round trips, offline/reconnect/restart, stale replay, privacy and failed-readback safety. `service/test/worker.test.js` exercises the real Worker and D1 endpoint, authentication, account isolation, atomic conflicts, tombstones and strict payload rejection. `tools/issue-252-records.test.js` executes these production Zig cases and mutation/baseline controls on GitHub only. Lightweight inventory/integration checks do not invoke a compiler or suite.
